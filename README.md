# 益民幼兒園 — FHIR 智慧行政：出勤打卡與薪資核銷一體化系統

以 **HL7 FHIR（R4）** 國際醫療資訊標準打造的幼兒園人事出勤與發薪解決方案。
依《FHIR 智慧行政建置計畫書》實作，將「排班 → 打卡 → 結算 → 簽核 → 撥款」全流程數位化，
所有資料皆以標準 FHIR 資源儲存並上傳至 **HAPI 公開測試伺服器** `https://hapi.fhir.org/baseR4/`。

```
員工/會計 ──► 2 個 HTML 操作端 ──► Node.js 後端 ──► HAPI FHIR baseR4
```

## 兩個操作端（HTML）— 對應計畫書「雙系統架構」

| 檔案 | 操作端 | 對應角色 | 說明 |
|------|--------|----------|------|
| `public/clock.html` | 🕒 **員工打卡端** | 員工 | 現場點名簽到/簽退、自動換算十進位工時、查詢本人出勤。**免登入（櫃檯公用）、不顯示任何薪資與他人資料，也沒有通往簽核的入口。** |
| `public/admin.html` | 📊 **會計室核銷端** | 會計／園長 | 人事、排班、出勤稽核與補登、月底結算、線上簽核、產生核銷清冊與合庫媒體撥款檔。**需密碼登入。** |

### 兩端的權限隔離（打卡端看不到簽核）

- **員工打卡端**免密碼、僅能呼叫 `/api/clock/*`（最小揭露：只有姓名/編號/綁定狀態）。
- **會計室核銷端**需密碼登入（預設 `admin1234`，請以 `ADMIN_PASSWORD` 變更）；所有簽核/薪資/人事/排班/撥款 API（`/api/practitioners`、`/api/scheduling`、`/api/attendance`、`/api/claims`、`/api/payout`）一律需授權，未登入直接呼叫會回 `401`。
- 打卡頁也已移除通往核銷端的連結，櫃檯人員無法從打卡端進入或看到簽核功能。

## FHIR 資源模型（七項核心資源）

| 系統模組 | FHIR Resource | 核心防錯機制 |
|----------|---------------|--------------|
| 人事資料 | `Practitioner` | 依本薪自動判定薪資模式（>0 月薪制／=0 純時薪） |
| 可排範圍 | `Schedule` | 定義人員可被排班的時間範圍 |
| 可排時段 | `Slot` | 標記 free/busy，避免重複排班 |
| 排班預約 | `Appointment` | 預約佔用時段 |
| 簽到退打卡 | `Encounter` | 依打卡時間自動換算十進位工時 |
| 會計結算 | `Claim` | 工資必須綁定出勤證據，否則阻斷 |
| 園長發薪 | `ClaimResponse` | 核准後自動生成銀行媒體檔 |

**數位證據鏈**：`Schedule/Slot → Appointment → Encounter → Claim → ClaimResponse → 合庫媒體撥款`，
每筆薪資皆可向上回溯至對應出勤與排班紀錄（透過 FHIR 資源間的 reference 與 `Claim.supportingInfo`）。

## 加值功能

| 功能 | 說明 |
|------|------|
| **勞健保自動計算＋手動覆寫** | 月薪制可在人事資料填「投保薪資」，系統依員工自付費率（勞保 2.4%、健保 1.55%，可在 `.env` 調整）自動算出代扣金額；亦可取消勾選「自動計算」改為手動覆寫個別金額（例如沿用 930／1,510）。純時薪制一律封鎖代扣。 |
| **收入流水號** | 每筆結算（`Claim`）產生唯一流水號 `S年月-序號`（例 `S202606-0001`），帶入 `ClaimResponse`、簽核清單、核銷清冊、撥款預覽，並寫入 `salary.txt` 每一行，方便對帳。 |
| **跨日未簽退提醒** | 未簽退（in-progress）即標記異常；若**跨日仍未簽退**，會計端列為「待立即處理」置頂、員工打卡端選到本人時跳出紅色提醒，並可直接補登實際離開時間（隔天即時處理）。 |
| **打卡綁定個人裝置** | 員工首次以自己的手機打卡即綁定該裝置，之後僅限同一支手機打卡（防代簽）；非綁定裝置會被擋下並提示。會計室可一鍵「解除綁定」讓員工換手機重新綁定。 |
| **帳號清楚顯示** | 銀行帳號以等寬字體完整、不截斷顯示，並標明銀行（如「合作金庫（006）」），套用於人事清單、撥款預覽與核銷清冊。 |

## 快速開始

需求：Node.js 18 以上（已用 v22 測試）。

```bash
npm install          # 安裝相依套件（僅 express）
npm start            # 啟動後端，預設 http://localhost:3000
```

開啟瀏覽器：

- 首頁（入口）： <http://localhost:3000/>
- 員工打卡端： <http://localhost:3000/clock.html>
- 會計室核銷端： <http://localhost:3000/admin.html>

### 灌入範例資料（建議）

```bash
npm run seed
```

會在 HAPI 伺服器建立計畫書情境 A／B 的範例（含排班與整月出勤）。
完成後到「會計室核銷端 → 月底結算」即可直接看到：

- 王曉明（月薪制）實發 **NT$43,640**
- 陳小美（純時薪）實發 **NT$8,645**

## 操作流程（對應計畫書四大情境）

1. **人事資料**：新增員工（可按「填入情境A／B」快速套用範例）。本薪填 0 即自動切換純時薪制；月薪制可填「投保薪資」由系統自動算勞健保，或取消勾選改為手動覆寫。
2. **排班**（情境 A）：建立 `Schedule` → 新增 `Slot` → 預約 `Appointment`（時段自動轉 busy）。
3. **打卡**：員工於自己的手機選擇姓名與工作類別（正常班／課後延護／行政加班）後簽到、簽退；**首次打卡綁定該手機**，之後僅限同裝置。
4. **出勤稽核**（情境 D）：未簽退者標記「缺簽退」、跨日未簽退列為「待立即處理」置頂，可一鍵補登簽退，工時自動重算。
5. **月底結算**（情境 A／B）：選人員與期間後結算，產生**收入流水號**；**若有缺簽退會阻斷並列出待修正清單**。月薪制／純時薪由系統自動裁決。
6. **簽核發薪**：園長核准 → 建立 `ClaimResponse`；可「列印核銷清冊」（列印時自動隱藏操作按鈕，僅保留財務總表）。
7. **撥款媒體檔**（情境 C）：一鍵下載合作金庫媒體轉帳檔 `salary.txt`（格式：流水號＋銀行代碼＋帳號＋金額＋姓名）。

## 設定（環境變數，皆有預設值）

複製 `.env.example` 為 `.env` 後可覆寫；或直接以環境變數帶入。

| 變數 | 預設 | 說明 |
|------|------|------|
| `PORT` | `3000` | 後端服務埠 |
| `FHIR_BASE_URL` | `https://hapi.fhir.org/baseR4` | 目標 FHIR 伺服器 |
| `TENANT_TAG` | `morninglight-kg-demo` | 租戶標記（見下） |
| `CURRENCY` | `TWD` | 幣別 |
| `BANK_CODE` | `006` | 合作金庫銀行代碼 |
| `LABOR_INS_RATE` | `0.024` | 勞保員工自付有效費率（自動計算用） |
| `HEALTH_INS_RATE` | `0.0155` | 健保員工自付有效費率（自動計算用） |
| `ADMIN_PASSWORD` | `admin1234` | 會計室核銷端登入密碼（打卡端免密碼） |

> **關於公開伺服器與租戶標記**：`hapi.fhir.org` 是全球共用的測試伺服器。
> 本系統將每一筆資源都貼上 `meta.tag`（system 為 `http://morninglight.kindergarten/fhir/tenant`），
> 且所有搜尋都以 `_tag` 過濾，因此只會讀寫「本園」資料。
> 若多人使用相同的 `TENANT_TAG`，會在公開伺服器上看到彼此的資料，
> **建議將 `TENANT_TAG` 改成獨一無二的字串**（例如加上學號或亂數）。

## 模型化備註

- 計畫書將「薪資請款/核准」對應到 FHIR 的 `Claim`／`ClaimResponse`。FHIR 規定 `Claim.patient`／`ClaimResponse.patient` 只能指向 `Patient`，故本系統為每位員工建立一個對應的「受款人 `Patient`」（以員工編號 identifier 連結、可重複使用），`Practitioner` 則維持為人事主體。結算時會自動建立或重用該 Patient。
- 薪資/保費/銀行等非標準欄位以自訂 `extension` 承載於 `Practitioner`；
  完整薪資明細以 JSON 存於 `Claim`／`ClaimResponse` 的自訂 extension，方便前端原樣呈現與產生媒體檔。
